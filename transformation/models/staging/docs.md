{% docs stg_account %}
Staged Salesforce account records with light renaming.
Each row represents a single Salesforce Account object.
Accounts are the central entity linking opportunities, contacts, and cases.
{% enddocs %}

{% docs opportunity_stage_bucket %}
Categorisation of opportunity stages into business-meaningful buckets
generated by the 'sf_stage_bucket' macro:

| Bucket | Stages |
|--------|--------|
| **pipeline_early** | Prospecting, Qualification, Need Analysis, Value Proposition, ID Decision Makers |
| **pipeline_late** | Perception Analysis, Proposal/Price Quote, Negotiation/Review |
| **closed_won** | Closed Won |
| **closed_lost** | Closed Lost |
| **other** | Any unrecognised stage |
{% enddocs %}

{% docs surrogate_key_pattern %}
All dimensional models use an MD5-based surrogate key generated via
'dbt_utils generate_surrogate_key' (wrapped by 'sf_generate_surrogate_key').
This decouples analytics keys from Salesforce natural IDs and provides a
stable, deterministic key even when source IDs are alphanumeric.
{% enddocs %}

{% docs incremental_case_events %}
'int_salesforce_case_events' uses an **incremental** materialisation with the
'delete+insert' strategy. On each run only events newer than the latest
'event_timestamp' already loaded are processed, keeping rebuild cost low
while guaranteeing idempotency through the 'case_event_sk' unique key.
{% enddocs %}
